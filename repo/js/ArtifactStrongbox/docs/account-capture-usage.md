# 角色仓库录入

当前运行版本：0.9.3。2026-10-29整理：本页保留录入实现的阶段记录；首次操作见 [README](../README.md)。已录入装备和推荐现已参与三合一候选与逐角色分析，详见 [当前判据](role-assessment.md)。

0.7.2使用 [录入完整性与姓名容错](capture-quality.md) 规则：字典名优先、无装备者标记不录入当前装备、按确认的套装种类清洗件数，仅跳过信息完整的角色。0.7.0加入的名称字典与特殊自定义身份继续保留，详见 [名称与增量录入说明](character-names.md)。

关闭录入后，普通模式直接进入三合一遮罩，不强制打开角色选择窗口。可在遮罩内勾选培养角色，也可启用 [独立选择模式](training-characters.md)；两者按用户标识保存名单。

更新：2026-10-26（Asia/Shanghai）。已实现录入、录制整理与离线回归；尚未在 BGI 中完成一次全角色游戏遍历。读取失败会保存待核对状态。0.6.1增加 [运行日志](runtime-logging.md)，启动时显示本次路径。

0.5.2根据用户实际部分录入结果修复：主推荐“×4”漏读导致不点击、装备者混入物品说明，以及角色名称过度依赖左上标题。现有账号文件仅作为只读诊断依据，没有修改历史记录来伪造成功。

## 使用

1. 使用原神简体中文、1920×1080、默认布局，在 BGI 刷新此 JS 脚本配置。
2. 填写“用户标识”，可用 UID 或“主号”等1～40字标识。不同账号使用不同标识。8～12位纯数字按 UID 处理，识别到游戏 UID 后会核对；其他标识也会与已读到的 UID 绑定，已有绑定不符时停止。
3. 勾选“运行角色仓库录入”。开关默认关闭；关闭时原三合一预测流程照常运行。
4. 开启后本次只录入：必要时逐次 Esc，通过派蒙图标确认大世界后发送首次 C。无法确认时停止，不盲按 C。
5. 读取属性页名称、五件物品及装备者、各部位推荐属性；首个成功推荐面板点击使用率不低于10%的套装图标，读取名称与件数。低于10%的行标记跳过，不影响本轮完整性。
6. 返回概览 E 切角色，绕回起始角色时结束。正常结束停在起始角色属性页，不继续进入三合一。日志给出保存文件和待核对角色数。

所有C/E/F/Esc和鼠标点击都是完整短按／点击，**动作后默认等600毫秒**，动作计划值限制在500～1000毫秒。两帧语义复核之间只等120毫秒；部位切换直接确认两帧详情，不再先确认两帧页面后重复读取。down/up仍由BGI一次完成。以上是主动等待，截图和OCR耗时另计，不能保证每步总时长都小于1秒。

0.5.1按阶段减少OCR区域：页面检查只读锚点，保存详情时读取物品列，推荐和名称弹窗分别读取对应区域。日志显示角色名、当前部位、物品名/等级/套装、推荐摘要和保存进度；未稳定时提示正在复核，不展开全部词条。未装备和循环判定沿用0.5.0，本次没有进行这两项游戏实测。

角色名与详情的主识别范围为 `(1460,110,460,970)`，覆盖到右、下边缘。0.6.1同时读取左上 `(125,20,350,60)` 中完整的“草元素/纳西妲”等标题。右侧有等级、体力上限或好感度等属性证据时才把该区域文字当作姓名；右侧漏读时，可使用完整左上标题与角色菜单。两侧冲突时重新点属性并聚焦复核，不再无条件相信右侧。元素缺失不用于判断是否绕回起点，旧记录也不因补齐元素而重复建条。

返回概览时，优先使用左上标题，右侧“套装效果／圣遗物详情”等普通文字不参与姓名判断。未稳定匹配当前角色时，点击属性重新识别；只有复核仍为其他角色，才报告包含预期与实际姓名的错误并停止。尚未确认身份时不按E继续，未放宽装备者匹配条件。

0.6.2保留首次4帧、重新点击属性一次后4帧的上限。重试左上裁剪改为`(130,24,340,48)`，右侧姓名改为`(1450,110,470,80)`，覆盖区域按截图实测校准。左上允许分隔符漏读或竖线；若OCR明确拆为“元素”“1”“姓名”三个框，仅把中间框作为斜杠处理，姓名字符不做替换。参考图实际OCR的新旧裁剪输出保存在`tools/fixtures/identity-retry-ocr.json`。

常规两帧一致仍优先通过。两轮未形成稳定结果时，汇总最多8个独立采样帧的姓名候选：获胜名称至少出现于3帧，比次名多至少2帧；有竞争名称时，胜者必须获得左上、右侧两种来源支持。两边持续各说一个名字、证据太少或票数接近都不强行选边；保留进度并输出原文后停止。当前姓名归一化使用独立角色名称字典与特殊角色介绍，不使用评分库覆盖范围代替名称字典；生僻字、字母混入的容错详见 [姓名规则](character-names.md) 与 [完整性规则](capture-quality.md)。跨帧投票只用于姓名，不拼接圣遗物数值。

等级须在1～120的解析合理区间内且不超过读取到的上限；这是OCR异常过滤区间，不表示游戏实际等级上限。`901`等读数记为null，不擅自改成90，也不单独构成属性页证据。

详情或装备者首次未确认，重新点当前部位一次，再分别读取名称、主副词条、套装和装备者小区域。装备者只取含“已装备”的一行，排除上方长说明。第二轮仍不完整但已确认仍在该部位时，保存 `unknown` 观察并继续其他部位；角色身份两轮仍无法确认则停止并保留进度。真正他人物品仍不会写为现装，不能通过模糊姓名匹配强行通过。

录入时间随角色数及重试次数增长。BGI停止快捷键可取消，代码会尝试同步保存当前角色部分结果并释放资源，不在取消后继续导航。

## 文件与覆盖

文件位于脚本下 `data/accounts/`，例如：

```text
uid-123456789.json
uid-123456789.pending.json
uid-123456789.backup.json
```

非数字标识编码为 `id-<字符编码>.json`，避免Windows大小写、路径字符及保留名称冲突；实际 `accountId` 保存在JSON内。用户标识不自动从参考图或聊天中填写。

- 同标识再次运行时，已读取的同角色、同部位、同推荐字段覆盖旧值；没有本轮观察的字段保留原时间，不重复追加角色。
- 每个角色完成后保存，异常或取消时保存当前角色已读取字段。`scan.status` 为 `running/complete/failed/cancelled`；`complete` 表示完成导航循环，字段完整性另看各角色状态。
- 本轮装备者不匹配或不可读时，`equippedArtifact` 为 `null`；旧的已核验物品仅保留在 `lastVerifiedArtifact`，不冒充刚确认的现装。失败推荐与 `previousVerified` 历史记录分开。
- 写入顺序为 pending→回读→旧提交内容备份→主文件→回读。这里没有原子替换事务；下次加载会从同账号合法副本中选最高revision。全部副本损坏时拒绝覆盖。
- `manifest.saved_files` 包含 `data/accounts`，保留本地账号资料。

## 数据与边界

账号文件包含 `schemaVersion/accountId/observedUid/revision/scan/characters`。每个角色有：

| 字段 | 内容 |
| --- | --- |
| `identity` | 右侧属性页名称、左上参考、元素、等级、来源与识别轮数 |
| `slots[部位]` | 状态、观察装备者、选中物品、已确认现装或历史记录 |
| `recommendations[部位]` | 本部位主／副词条推荐、顺序、使用率、时间和状态 |
| `setRecommendations` | 搭配组成、件数、使用率、名称OCR来源及来源部位 |
| `complete` | 五部位归属、推荐和套装名是否均已读全，不代表培养意图 |

推荐按“主要属性／追加属性”标题动态定位，不把冠的主词条列表复制给沙、杯。套装名称来自说明卡标题OCR，保存 `clicked-title-ocr` 来源；2+2分别读取。使用率低于10%标为 `skipped_low_usage`；正好10%仍读取。“×4”不清时也先点击第一图标读取名字，必要时探查第二图标。0.7.2在确认只有一个套装时补全4件，确认两个不同套装时补全各2件；第二名称读取失败则仍保留未知，不将失败当成单套。

点击坐标固定为：第1行 `(925,125)/(1065,125)`，第2行 `(925,225)/(1062,225)`，第3行 `(925,325)/(1065,325)`，保存在动作计划。没有第二图标时保持推荐面板，不误发Esc退出角色。

**右下角装备者须等于当前角色，部位正确且两次语义一致，才写入现装。** 短暂坏帧不再清空已经出现的有效候选，不拼接不同帧的物品数值。默认选中他人物品记 `selected_foreign`；归属或字段不全记 `unknown`，不视为确认空部位。星级仍为null。本版不自动装备、卸下、重塑、锁定或合成。

E在概览切角色、详情切部位。部位切换失败时，仅在确认仍为详情页后点对应图标纠正。角色E后同名停留最多尝试三次；非起始角色重复、姓名不稳定等保存进度并报错。经过其他角色后回到起点才正常结束，不重复保存起点。

仅一个可遍历角色时不能仅凭同名区分切换失败，本版提示而不宣称完成。保护上限为256角色、4小时及各页面有限重试。每次启动从当前起点遍历，可开启“跳过已有数据角色”；身份、现装、推荐等仍有未确认字段的角色不会被跳过。

## 开发与验证

```text
node tools/normalize-account-recording.mjs
node tools/verify-all.mjs
```

整理工具选择 `User/KeyMouseScript` 中文件名时间最新的原始录制，核对按下/松开及操作结构，生成 `assets/account-capture-actions.json`，原录制不修改。当前来源 `BetterGI_GCM_202610251522113457.json`，四段、44个完整操作。运行时加入页面验证和循环，不盲回放四段后结束。

测试涵盖账号隔离、UID冲突、同字段覆盖、备份恢复、写入错误、装备者、状态导航、E纠正、起点/异常重复、取消保存、入口隔离与资源释放。

`tools/fixtures/account-reference-ocr.json` 保存11张本地参考图的实际RapidOCR输出，五部位字段、装备者、名字、推荐属性与件数均已对照人工表通过；三张强匣图也验证为非角色页。Node可直接重放这些结果，无需OCR依赖。

可选开发工具 `tools/extract-account-reference-ocr.py` 需要 `rapidocr-onnxruntime/numpy/Pillow`。本轮依赖安装在临时目录，未加入BGI运行依赖。RapidOCR与BGI引擎/预处理可能不同，不能代替BGI整轮实测；套装弹窗及空部位负例仍需验证。

已录入资料参与当前三合一候选与现装比较；早期“尚未接入”的阶段限制已被后续版本替代。候选来源与三色判据分别见 [推荐接入](strongbox-recommendations.md) 和 [逐角色取舍](role-assessment.md)。

接口依据：[BGI图像OCR](https://www.bettergi.com/dev/js/rec.html)、[输入方法](https://www.bettergi.com/dev/js/global.html)、[文件读写](https://www.bettergi.com/dev/js/file.html)。
