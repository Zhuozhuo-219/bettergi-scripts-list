# 受现有套装限制开关（0.9.3）

更新：2026-10-28。遮罩顶部新增“受现有套装限制”，默认勾选。按F7进入交互后可切换，本次运行有效，重新启动恢复开启。

## 开启与关闭

开启时沿用当前判据：五部位现装可靠，替换后保留已有四件套/两件套效果；会拆套装则待定。

关闭时不以破坏已有套装组合拦截，比较候选与同部位现装的属性评分。其他部位未录全不再阻止这项比较，但同部位装备者、数据完整性、满级基准仍须可靠。若全套件数不明，会保留未知状态，不根据不完整资料编造件数。

关闭并非忽略所有限制：>15%主词条推荐范围、跨主属性统一计价、非0级素材保护、现装满级/数值/归属检查和三模型概率判据仍有效。原评分和角色权重不变，不自动操作游戏物品。

这与“适配套装角色”是独立的两个选项：“适配套装角色”决定候选来源，“受现有套装限制”决定是否要求保持该角色现装套装。关闭后不会自动把全部角色加入评分，仍按开启的三种来源取并集。

## 显示与缓存

关闭后顶部显示“已忽略现有套装组合，仅作属性评分对比”，计数说明也标注“忽略套装”。若确实会拆散已知套装，角色行追加“已忽略拆套装”；悬停注明未计算套装效果损失。因此绿色只表示属性评分提升，不宣称实际换装后伤害一定提高。

开关进入预测缓存键，切换后清除旧分析显示并重新计算标签和三色计数；同一件素材的强化样本和原分位数保持一致，便于在两种约束下对照。日志记录本次`assessmentOptions.respectExistingSets`，已完成比较的角色记录也保留模式和已知的被破坏套装。

为兼容旧版HTML消息，缺少该字段时保留本次值；显式非布尔类型拒绝。关闭后重新勾选会恢复保护，不复用无约束结果。

## 验证

`node tools/verify-all.mjs`验证拆套装素材开启时待定、关闭后可按纯分数保留、重开恢复、模式缓存隔离、随机样本一致、缺其他部位/同部位归属保护，以及HTML勾选、提示和真实入口传参。开发预览可用`node tools/preview-strongbox.mjs <账号> 2600 ignore-sets`只读查看关闭模式。尚需BGI游戏内验证。
