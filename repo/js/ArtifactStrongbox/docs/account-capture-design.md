### 时间标准化（0.5.1按最新要求缩短等待）

0.5.0曾按至少1秒执行；用户实测反馈等待叠加，0.5.1改为动作后默认等600毫秒、两帧复核之间等120毫秒。[动作计划](../assets/account-capture-actions.json)仍保留44个完整操作与原始时间、按住时长，忽略轨迹。

原录制按住约81～169毫秒。运行时仍用BGI `keyPress/click` 完成短按，不将down/up拉成长按；动作等待限定500～1000毫秒。详情切换直接核对两帧数据，不再先做两帧页面检查；页面、身份、详情、推荐和弹窗分别读取需要的OCR区域。截图识别耗时另计，不能承诺每步总耗时都小于1秒。

固定等待是最低等待策略，不能保证动画已完成。后续应以连续两次读取到稳定的页面、名称、部位及字段作为采集条件，失败时有限重试；不要比较整帧像素是否完全相同，背景和光效会变化。

## 5. 装备者核验与空部位

这是采集现装的硬条件：**当前扫描角色身份必须来自属性页；详情页识别到的装备者与它可靠匹配后，才允许把该物品作为当前角色该部位的现装。**

每一步先确认预期部位，再从同一帧读取物品字段和装备者。等待第二帧语义稳定，避免切换动画里把上一件的装备者与下一件的数值混在一起。仅去除明确的 OCR 空白、统一 Unicode 表示和已知“已装备”后缀，不进行任意模糊姓名匹配；自定义姓名与评分库角色映射另行保留。

| 观察结果 | 建议状态 | 保存规则 |
| --- | --- | --- |
| 装备者清晰且等于当前角色，部位正确，字段稳定 | `equipped` | 可写该角色对应部位的已核验现装 |
| 装备者清晰但为其他角色 | `selected_foreign` | 仅保存选中物品观察，不写当前角色基准，不将该姓名改成当前扫描角色 |
| 明确选中未分配物品 | `selected_unassigned` | 不能仅凭它推断当前角色该部位为空；不写现装 |
| 装备者区域为空、OCR失败或页面未稳定 | `unknown` | 重试或保存未完成，不当作空部位、不当作0分 |
| 有独立证据确认当前角色这个部位未佩戴 | `empty_confirmed` | 可以记录空部位；确认方式仍需补反例截图和实测 |

用户已说明：原本没有佩戴某部位，进入详情仍可能默认选择其他角色或无人装备的背包物品。所以 `selected_foreign` 不能直接等同于“已证明为空”，也不能把该物品归给当前角色。记录原始观察与推断状态，避免丢失证据。

“卸下”文字、选中框、角色模型和左侧小头像可作佐证，不能代替右下角装备者匹配。若需要定位当前角色真正装备的物品，应单独验证导航方式，不自动装备或换装来制造一致状态。

采集器还需接受低星级、+0、未强化满级、少于四条副词条等合法现装。当前强匣预测器只支持五星，不能把它的四词条/+20终值验证直接当成所有角色现装的读取条件；星级未知应保存未知，不能猜作五星。

## 6. 导航与循环状态草案

```text
首次 C
  → 属性页：读取并固定角色身份
  → 圣遗物概览：核对身份与页面
  → F：确认详情页且当前为花
  → 花观察 → E → 羽观察 → E → 沙观察 → E → 杯观察 → E → 冠观察
  → 展开推荐并采集 → 收起参考
  → Esc：确认已回到该角色圣遗物概览
  → 保存本角色采集结果与缺失项
  → E：下一角色
  → 属性页：稳定读名，进行循环判断
```

原录制只有冠的推荐展开节点；0.5.0已为各部位增加推荐采集，并在首个面板读取套装名称弹窗，不盲按E/Esc拼接。F默认进入花仍会逐次验证，不一致时校正或报告未完成，不能把羽的数据标作花。

建议区分导航访问集合 `visitedCharacters` 与数据完整集合 `completedCharacters`：某个角色因空部位或识别异常而未完成，不应导致角色循环永远无法结束。

| 切换后稳定身份 | 处理 |
| --- | --- |
| 与上一角色相同 | 视为切换未完成或失败；有限等待／重试，不认为已绕完一圈 |
| 新角色 | 加入访问记录，继续采集 |
| 已经过其他角色，重新到起始角色 | 在重复采集前正常结束；报告本轮完整／不完整角色数 |
| 重复一个非起始角色 | 视为序列、筛选或识别异常；保留进度，不静默宣布扫描完毕 |
| 身份不可读或两个名称来源冲突 | 不推进角色计数，不把装备者当作角色身份；有限重试后保存异常 |

只有一个可遍历角色时，同名停留与 E 未生效无法仅靠名称区分，应结合角色列表或明确配置处理；不在缺少证据时无限重试或声称完整遍历。

确认详情与弹窗均已关闭才执行切角色 E。Esc 若只关闭了一层弹窗，应重新识别状态，不盲目连续 Esc 退出角色界面。保持进入时的角色列表和筛选状态，不能假定遍历一定覆盖未拥有角色或全部流派。

每个状态设置有限重试、总步数／时间上限和取消检查；具体上限待实测配置。取消或失败时保存可审查的部分结果并释放图像等资源。读到空名不算正常终止。

## 7. 原数据记录建议与实现对应

0.5.0已确定第一版运行格式，见 [使用说明](account-capture-usage.md)。下列建议保留为设计依据：现装、观察、历史核验和推荐状态分开，未识别字段不伪装成已确认数据。

当前 `assets/character-profiles.json` 是评分条件配置，**不是扫描输出文件**；不要把未经核验的账号观察直接覆盖它。采集事实与派生评分分开保存。

一条角色采集记录建议包括：

- 角色显示名、可选规范角色标识、元素、身份读取来源、采集时间、页面尺寸及采集器版本。旅行者／可改名角色允许保留未映射身份，不能因不在角色字典而丢弃。
- 五个固定部位键，每部位有 `status`、`observedOwner`、物品原始文本及规范字段、来源帧／截图引用；只有核验成功才有 `equippedArtifact`。
- 套装推荐方案列表，每个方案含组成套装及件数、顺序、使用率、来源；保留四件套与2+2的区别。
- 按部位保存主词条推荐和副词条推荐顺序，保留未展示、未读取与明确空列表的区别。
- 身份、现装、推荐各自的完整性／错误状态和最后核验时间；另存用户培养意图，不把“拥有”自动设为“培养”。

先在临时角色记录中采集，校验后提交。0.5.0用pending、backup和回读保留可恢复副本；本轮归属未知时当前 `equippedArtifact` 为null，旧核验物品另存 `lastVerifiedArtifact` 并保留核验时间，不能伪装为刚更新。空部位与未完成角色不使用零分基准。

若现装低于 +20，应注明比较的是当前成品，还是双方推进到同等培养条件后的潜力。充能、暴击等整套信息未收集时保留未知；属性页基础五行不包含完整暴击和充能面板，不能声称已经采齐。

## 8. 图像识别与点击文字两条路径

可使用 [miao-plugin artifact/imgs](https://github.com/yoimiya-kokomi/miao-plugin/tree/master/resources/meta-gs/artifact/imgs) 建立图像候选。此前已人工查看黄金剧团和华馆的透明底 `1.webp`；原图尺寸不同，游戏图标有底框和右上角部位徽标，不能假定原图原尺寸直接匹配可靠。

图像路径需统一内容尺度、排除背景／徽标干扰，并在六个候选区域识别有效占位。匹配置信不足或第一、第二候选相近时保留未知，不强行取最大值。

文字路径为“点击有效图标→确认套装说明弹窗→读名称→只关闭这一弹窗→确认回到推荐面板”。本批参考图没有套装说明弹窗，相关区域和关闭方式待补图实测；不把此前聊天中的估计坐标当作已验收常量。

可试验图像给候选、文字确认疑难项，并在文字确认后缓存游戏内图标样本。同套装在多行重复时可复用名称判断，搭配关系仍各自保存。这是候选方案，尚未实现或作准确率承诺。
