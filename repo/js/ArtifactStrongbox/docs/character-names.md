# 7.1角色字典、自定义名称与增量录入（0.7.2）

更新：2026-10-27。名称字典与评分权重分别维护，本次不修改评分公式或角色权重。0.7.2新增混入字母清洗和字典优先策略，见 [录入完整性与姓名容错](capture-quality.md)。

## 名称来源

`assets/character-names.json`来自开源[miao-plugin角色元数据](https://github.com/yoimiya-kokomi/miao-plugin/blob/master/resources/meta-gs/character/data.json)，保留源blob SHA和实装时间。按`eta <= 2026-10-26`筛选7.1已实装条目，排除11月才实装的米提亚、瓦列里。当前125个名称条目包含空、荧、旅行者及两个人偶变体，不等于125名不同可玩角色。简介模板同样来自该项目的流浪者、奇偶、旅行者数据；许可证沿用项目已有的MIT来源声明。

字典优先精确匹配，再计算编辑距离。菈/拉、涅/湿、妲/姐等已观察到的易混字使用较低替换代价；一般短名字最多1次编辑，5字及以上最多2次编辑且总代价不超过1。候选太远或最近两名差距小于0.15时保留原文，不强行归一化。左上与右侧各自匹配后再交叉验证，装备者也使用同一字典和账号别名。姓名原文、匹配方式、距离及候选保存在`rawNames/nameNormalization`与日志中。

最新实际失败为左上“拉乌玛”、右侧“乌玛”连续8帧冲突，字典均可唯一匹配“菈乌玛”。原始失败帧已去除UID后固定为开发回归样例。

## 自定义名称

先对右侧介绍做文字归一化与模糊匹配，再尝试标准名字字典。识别至少需要16字、整体模板相似度≥0.66，以及至少两段介绍特征达到0.7。不会仅凭“人偶”或“流浪”两个字确认身份。

- 流浪者：匹配“身份成谜的流浪人士”“衣着打扮像是修验者”等介绍，统一为`流浪者`，游戏自定义名保存为账号别名。
- 千星奇域人偶：匹配魔女、派蒙、人偶、千星奇域和封存奥秘等组合介绍。按首次确认的不同自定义名固定为`人偶A`、`人偶B`，不推断性别；后续按账号别名精确对应。名称相同无法可靠区分两个人偶，第三个未知名字也不擅自当成其中之一。
- 旅行者也有可改名边界：0.7.1起通过介绍、标准主角名或已确认别名，统一为`旅行者（元素）`，覆盖七种元素；无法确认的自定义名继续保留。当前元素未读到时拒绝确认，不沿用历史元素，见 [旅行者和OCR处理说明](traveler-and-ocr.md)。

同一张图已确认特殊身份时，左右姓名相差1字可使用右侧姓名，但两个人偶之间的别名不做模糊合并。常规两帧稳定校验包含自定义名，不能让不同原文仅因都被暂称“人偶A”而通过。自定义名与标准角色重名、导致装备者无法区分时，保存为未确认，不能当作已装备。

人偶A/B的存储键不随元素变化；若检测到元素改变，要求重新读取五部位，跳过选项不会绕过此次刷新。旅行者按元素保留记录。介绍模板只用于识别身份，不自动套用性别、武器或流派权重。

## 跳过已有数据

BGI设置`skipExistingCharacters`默认关闭。0.7.2起，开启后仍从大世界进入、逐位读取属性姓名并检测循环；只跳过身份、五部位当前装备、各部位推荐词条及主要推荐套装均完整的角色。未知装备者、他人默认选中物品、缺失词条、未读全套装或需要刷新元素的记录均继续录入。旧文件会重新核验，不仅依赖旧`complete`字段。结束日志分别显示本次录入数和跳过数。
