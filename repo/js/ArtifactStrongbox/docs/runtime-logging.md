# 运行日志（0.7.0）

0.7.0在身份日志中增加`rawNames/aliases/kind/nameNormalization`及介绍匹配证据，在装备者日志中保留`ownerRaw/ownerNormalization`。`character.skipped`记录已有五部位数据角色的跳过动作；原有JSON分片格式不变。

每次执行自动创建独立日志，启动时BGI日志显示“本次运行日志：…”；无需开启额外选项。日志保存在脚本内部的`data/logs/`，不改写角色仓库或此前日志。

使用UID标识时，先查看`data/logs/uid-<UID>.latest.json`，其中`path`指向最新运行目录的`run.json`。自定义标识沿用账号文件的编码前缀；未填标识的启动错误记录为`unassigned`。

每次目录包含：

- `run.json`：版本、运行模式、开始/结束时间、运行状态、事件数和分片数。进程被强制结束可能保留`running`，已写事件仍可查看。
- `events-0000.json`及后续编号：JSON事件数组，按`sequence`递增，每片最多64条。逐条覆盖写入当前有界分片并回读校验。

角色录入记录按键、点击坐标、识别范围、尝试次数、页面、姓名左右来源、装备者、推荐、复核条件是否通过与异常。身份关键区域保留OCR原文字及文字框坐标，不保存截图。`overview.check`包含预期角色，`overview.recheck`表示已回属性复核，`identity.mismatch`记录复核后仍不一致的具体名称。`run.error`包含错误消息和截取的堆栈。普通三合一模式在识别内容变化时记录详情和页面标记。

日志写入失败只提示一次，不阻断独立的账号数据保存。日志中的时间使用ISO UTC格式（`Z`结尾），与BGI本地时间对照时北京时间加8小时。日志含UID、角色和装备信息，分享前可按需处理。
