# 本阶段确认：评分数据与第四词条

本说明的评分分析依据工作区内 `ArtifactScore` 源码和用户提供的截图；原评分数据未更新。0.4.0 已将单件评分公式接到模拟后的 +20 终值，不直接使用 +0 当前分。网络核验、词条组合和当前模拟实现见 [projection-design.md](projection-design.md)。

## 1. 评分数据如何存储

`ArtifactScore/utils/artis-score-standalone.js` 是约 89 KB 的自动生成 ES Module，**数据和计算代码合并存储在本地 JS 中**，不是独立数据库文件，也不是运行时在线查询。实际导入检查得到 121 个角色的默认权重条目；这表示本地快照的内容，不表示当前游戏角色的完整覆盖。

| 内容 | 源码标识 | 作用 |
| --- | --- | --- |
| 词条尺度与映射 | `basicNum`、`attrPct`、`attrMapBase`、`attrMap` | 统一不同词条单位，区分固定值和百分比 |
| 主副词条候选 | `mainAttrOptions`、`subAttrList` | 计算各部位理论上限 |
| 角色默认权重 | `usefulAttr` | 按角色保存攻击、生命、双暴、精通等相对权重 |
| 角色基础属性 | `baseAttrMap` | 把固定值词条换算为相应的角色收益尺度 |
| 角色元素 | `charElemMap` | 元素杯匹配和旅行者元素分支 |
| 武器补正 | `weaponCfg`、西风武器规则 | 按所传武器调整部分权重 |
| 角色规则 | `artisDefaultWeights`、`charSpecialRules` | 默认流派覆盖及角色条件分支 |

数据更新入口是 `ArtifactScore/tools/crawl-standalone.js`。它从 miao-plugin 的 `artis-mark.js`、`extra.js`、`ArtisMarkCfg.js`、角色 `data.json` 和 `artis.js` 提取数据与规则，合入 `LOCAL_OVERRIDES`，然后重写独立模块；默认来源分支为 `master`。例如本地更新器对玛薇卡权重和特殊规则做了覆盖，因此该模块也包含维护者自己的选择。

生成文件声明来源仓库和分支，没有固定来源提交哈希；仅凭它不能还原每条规则的确切上游版本。新脚本以后若抽取数据，应另外保存来源、版本和抽取日期，避免混淆本地快照与实时资料。

`ArtifactScore/utils/artis-score-utils.js` 则手写维护五星副词条四档数值、命中次数估算、得分拆分和标色。它不会随更新器生成文件被覆盖。

## 2. 评分逻辑

1. `main.js` 从角色圣遗物界面读取部位、当前主词条数值和副词条，并标准化为 `pos`、`mainKey`、`mainValue`、`subs`。百分比生命/攻击/防御与固定值严格使用不同键。
2. `getAttrWeight` 根据角色选权重，并视参数应用特殊规则、命座、面板、武器和套装修正。特殊规则可能直接返回，跳过后面的默认补正。
3. `buildAttrs` 将权重转换为每单位词条的分值。普通词条大致为 `权重 / 单次最高档尺度`；固定值生命/攻击/防御还参考角色基础属性，固定攻击使用默认武器基础攻击补正 520。
4. `getMaxMark` 给每个部位构造归一化基准：沙/杯/冠计入最佳主词条的 `2 × 权重`；从允许的副词条中排除所选主词条，取最佳四项，第一项按 6 次、其余各按 1 次计入。这是理论基准，不是对当前胚子的未来强化预测。
5. `getMark` 按当前值求和：花、羽不计固定主词条贡献；沙、杯、冠主词条贡献为 `对应单位分值 × 当前主词条数值 / 4`；副词条按各项单位分值乘当前值累加。再应用主词条适配系数并归一化。

```text
单件分数 = 当前词条贡献总和 × (1 + fixPct) / 2 / 该部位理论基准 × 66
```

`fixPct` 由主词条适配度及代码中的充能、元素杯等分支决定。结果按一位小数输出；多件返回总分、均分，评级按均分划档。这里的 66 是归一化尺度，不是某件真实圣遗物未来一定能达到的分数。

### 普通分、角色分和展示分解的区别

- `analyzeArtifact` 遍历本地 121 个角色，旅行者默认取支持元素中最高的一项；按角色单件分降序排列，取前 `ceil(N/2)` 项均值作为普通分，另外返回前 10 个角色。
- 识别到角色时，大数字使用 `calcArtifactScore` 的该角色分。角色信息只由现有页面识别并缓存；不是完整读取配装。
- 未识别到角色时，大数字和评级使用上述普通分，但各词条贡献及标色的分解以**香菱**为基准；这些分项并不是前 50% 均分的逐项拆分。
- 单条贡献来自“全词条评分减去删掉该词条后的评分”；条件规则切换时属于差分结果，不一定等价于一个恒定线性权重。
- 分项的有效性颜色读取 `usefulAttr` 的默认权重，未完全同步动态规则和固定值换算后的权重，因此显示颜色不能独立作为取舍依据。
- `estimateSubStatRolls` 使用本地五星四档副词条数值，枚举 1～6 次的档位组合，取与显示数值最接近的一组；角标显示的是估算次数减 1。它不读取实际强化历史，也不能用于证明胚子初始三条还是四条。
- 现有脚本调用评分器时主要传入单件词条及元素，没有识别并传入完整武器、命座、队伍和套装上下文。评分器支持这些参数，不表示界面脚本已获得这些信息。

### 为什么不直接用于 +0 三合一取舍

评分器没有消费等级、初始词条数、待激活状态或剩余强化次数；它消费的是当前主副词条数值。低等级主词条更低、副词条尚未强化，直接按成品分数阈值处理会把“尚未成长”混同于“没有培养价值”。

离线调用例：按截图的生命杯输入主词条 7%、已生效副词条生命值 209、暴击率 3.1%、充能 5.8%，不把灰色攻击力 18 算进生效词条；本地普通分为 7.7，香菱分为 7.2。只把输入对象额外的 `level` 字段从 0 改成 20，而不改数值，评分仍为 7.2。这只是验证评分器不读取等级的控制实验，不是真实 +20 圣遗物样例。

可供后续复用的是词条标准键、数值尺度、角色需求数据和数据更新方式。胚子的候选角色、初始三/四条、待激活词条潜力、未来强化空间、套装需求及最终取舍阈值需要独立设计；本阶段不设这些阈值。

## 3. 截图能否区分第四词条

**用户提供的两类截图可以人工区分。** 第一张为 +0，第四行“攻击力 +18”呈灰色并带“（待激活）”；新提供的对照图为 +0 岩伤杯，副词条为充能 5.2%、固定防御 19、攻击 4.7%、固定攻击 16，第四行呈深色且无“待激活”。后者是初始四条。

| 证据 | 能否确认 | 当前实现 |
| --- | --- | --- |
| 第四行完整且明确读到“待激活” | 可确认该行待激活；+0 时可据此确认初始三条 | 已实现 |
| 四行完整可解析且均无“待激活” | 按用户提供的界面约定作为四条生效处理 | 第四条显示正常数值；+0 显示初始四词条 |
| 只检测到四行文本 | 灰色预览也占一行，行数不能区分 | 不以此推断初始四条 |
| 第四行相对前三行明显变浅 | 原始截图含有可用视觉证据 | 尚未实现颜色取样/分类 |
| 已强化的四条深色词条 | 只能说明当前显示状态，不能仅凭此还原初始三/四条 | 不推断初始词条数 |
| 第四行缺失或无法可靠解析 | 无法确认 | 待确认 |

BGI 的 OCR 返回文字与边界框；当前 `readOcrItems` 没有获得文字颜色。副词条状态使用 `activation: active/pending/unknown`，同时记录 `activationSource`；前三行在完整四行布局下的 `active` 是位置推断，来源为 `row-order`。第四行无标记时的生效推断来源为 `complete-rows-no-marker`，不声称已检测黑色像素。+0、四行完整且无标记时输出 `initialCount: 4`；第四行明确待激活时输出 3；其余为 `null`。

汇总字段 `fourthSubStat` 记录状态、证据来源与 `initialCount`。当前以两类界面的文字标记为依据，OCR 漏掉“待激活”可能造成误分；像素颜色可作为后续补强。原始 OCR 文本仍留在内部 snapshot，已从 HTML 展示和推送载荷移除。

### 后续可实施的颜色确认路线

可使用**同一张原始截图**中第四行文字的前景像素，与前三条深色文字作相对比较。应分割文字笔画、排除米色背景和抗锯齿边缘；不能只比较整块文字框的平均亮度，因为空白比例可能主导结果。用户现在已提供三条/四条各一个样例；仍需更多样例校准色彩/亮度阈值以及最低像素量、对比度和多帧一致性条件。

若将来接入颜色检测，文字与颜色证据不一致时可以触发重读。当前版本仅按文字约定处理，并未给出经过验证的颜色分类阈值或准确率。

## 4. 界面与验证范围

遮罩沿用参考 HTML 的金色边框、深色渐变、24px 圆角、阴影、双色主副词条和两列数值对齐；位置保持在游戏详情右侧。原始 OCR 展示及其配置项已移除；区域边框改为默认关闭。灰色行显示“待激活”，不确定行明确显示“待确认”，并单独展示初始词条状态。

0.3.0 已移植逐条强化命中次数估算，所有非 +0 名称变红。0.4.0 增加模拟至 +20 后的角色评分、两个降序分位及独立最高分分配；它表示当前数据快照与指定条件下的单件评分，不表示完整账号最优解。

离线检查覆盖初始三条/四条两类截图的字段样例、缺行、非 +0 情况、页面切换清空、消息桥接和截图资源清理。使用手工构造 OCR 输出，不代表已经运行真实 OCR。此前浏览器连接返回无可用实例，未完成视觉渲染预览；仍需在 BGI/WebView2 和原神内确认实际布局和识别效果。
