# 录入完整性与姓名容错（0.7.2）

更新：2026-10-27（Asia/Shanghai）。以下规则作用于角色仓库录入，不调整评分权重。

## 汉字混入字母

实际失败日志中，左上多帧为“七七”，右侧多帧为“tt”；两者同等参与冲突判断导致退出。已将该次八帧身份观察去除UID后固定为`tools/fixtures/character-name-latin-failure.json`。

标准名匹配先保留原始精确字典匹配，再尝试去除ASCII英文字母后匹配字典；例如“纳t西妲”恢复“纳西妲”。“七t”也可由既有唯一近似匹配恢复“七七”，不会将所有t无条件替换为七。无法匹配的纯字母或混合名不能作为普通角色身份，也不能通过多帧投票绕过限制。

左右结果优先级为：精确字典名、唯一近似字典名、未匹配原文。“七七/tt”选择七七；两个不同完整字典名仍保持冲突并重试。仅采纳获选身份的有效候选，保留`rawNames`、各侧匹配结果及`selectedSource`用于日志定位，不将“tt”这种失败读数登记成正式角色别名。

简介和已确认账号别名识别的旅行者、流浪者、人偶先独立处理，其真实英文自定义名保留。

## 当前装备与未知装备者

只有实际读到“xxx已装备”（兼容已有的己/備/各OCR混淆），归一化装备者匹配当前角色且详情完整时，才填入`equippedArtifact`。无标记与默认选中他人物品均不填当前装备，不推断为未佩戴；可保留`selectedArtifact`作为本轮观察证据。

首次缺失仍会重试一次。第二次详情稳定但装备者缺失时记录未知并继续扫描，不要求整轮退出。旧的可靠装备可以留在明确标为历史的`lastVerifiedArtifact`，不会充当当前装备。

## 推荐套装清洗

低于10%的组合继续跳过。主要推荐在完成图标检查后按套装种类补全：确认一个套装为4件套，确认两个不同套装为各2件。原件数保存在`rawCounts`，推导来源为`confirmed-set-composition`。

“只有一套”的确认依据为原件数已读到×4且无第二件数，或第二图标位置经稳定检查没有弹窗。若第二图标读取报错，或已读到×2但另一名称缺失，仍标记不完整，不能将识别失败误作4件套。两个图标读成同名也不强行确认为2＋2。

清洗在推荐读取后、角色合并保存时以及每次持久化检查点执行，因此正常完成、取消和异常退出保存都经过清洗。载入旧账号文件时先在内存重新校验，下一次检查点才写回，原始旧副本通过既有backup机制保留。

## 跳过与验证

跳过不再只看是否有五条记录，而是检查：身份已确认、无需刷新；五部位均有完整且归属匹配的当前装备；五部位推荐词条已读取；主要推荐套装均已确认。旧`complete:true`不能绕过这些检查。未佩戴或装备者持续未知的角色会再次尝试录入，这是保守保留未知状态的结果。

`node tools/verify-all.mjs`覆盖实际七七失败八帧、字母污染/字典冲突、自定义英文名、无装备者继续扫描、单套/双套件数清洗、第二名称失败保护、取消检查点和各类不完整角色不跳过。全套离线回归通过；尚需BGI游戏内实测。
