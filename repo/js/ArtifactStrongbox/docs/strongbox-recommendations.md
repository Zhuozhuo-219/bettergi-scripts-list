# 三合一候选与推荐数据接入（0.8.0）

0.9.0新增对照现装的逐角色三色标签和手动容量压力估计，候选排序仍按本页规则，原分位列保留。判据以 [逐角色取舍说明](role-assessment.md) 为准。

0.8.1将选人区改为独立宽面板，增加元素标签、拼音/首字母搜索及突出F7提示，见 [新版选择界面](character-search-ui.md)。本页候选与评分规则不变。

更新：2026-10-27（Asia/Shanghai）。本阶段实现候选筛选与交互，沿用已有通用角色权重，暂不新增取舍阈值或实际配装提升判断。

## 使用

先按账号录入角色资料，关闭“运行角色仓库录入”和独立“选择拟培养角色”选项，再运行脚本。普通三合一模式直接打开遮罩，不再强制先选一名角色。没有培养名单时仍可自动展示套装适配角色。

遮罩默认勾选“适配套装角色”“用户培养角色”；“匹配主词条（沙／杯／冠）”默认关闭。三个来源取并集，同一角色的同一评分分支只计算一次。关闭某一来源时，仍可从其他已开启来源入选。

按 **F7** 进入交互模式，可勾选来源、点击“选择拟培养角色”打开宽面板、搜索名称和滚动列表；再次F7或点击“返回游戏”恢复点击穿透并收起面板。长按F7只切换一次。交互期间暂停游戏截图，保留上一件圣遗物，返回游戏后重新截图核对。结束或报错均释放全局键盘监听。

角色表只展示当前账号已录入且身份未被拒绝的名字，默认按火、水、风、雷、草、冰、岩分类，组内按名称排序。支持滚动、搜索和清空选择；选择自动保存到原有账号`.training.json`文件，可以为空。来源开关只在本次运行中生效，重新运行恢复默认。旧独立选择窗口仍保留，但未录入名字不会加入新版推荐候选。

遮罩整体、角色表和评分表分别允许滚动。正常三合一模式返回所有入选分支，不再限制五行，旧“显示角色/分支数量”设置已移除。

## 套装来源

使用当前账号记录中`setRecommendations.rows`的已成功行：`status=ok`、使用率≥10%、组成名称和件数已确认。某角色其他字段不完整不妨碍采用这条已确认的推荐。低于10%的组合延续录入阶段的忽略规则，未读清的名称和使用率不参与。

匹配当前圣遗物套装名时保留该角色最优匹配：四件套优先于两件套，同件数取最高使用率。结果按以下顺序显示：四件套使用率降序、两件套使用率降序、仅用户培养角色、其余主词条适配角色。后两组按前20%分数降序。每行标注来源与对应使用率，多个来源可同时显示。

四件套、两件套的使用率是录入时的游戏推荐组合使用率，不是当前账号培养意图，也不直接乘到评分上。

## 主词条与散件来源

可选开启主词条匹配，仅作用于时之沙、空之杯、理之冠。读取该角色对应部位的成功推荐主属性，匹配词条名称及百分比/固定值单位。推荐必须有合法且非零使用率；使用率不被解释成属性权重。生之花、死之羽不走此来源，不把杯子推荐移用到沙或冠。

开启后，可将套装外但对应部位推荐该主词条的已录入角色加入评分，处理散件候选。未开启时，套装候选和用户勾选角色仍照常参与；本阶段不以主词条推荐排除这两类候选。

## 分数和缺失规则

表格只展示角色/分支、前20%、前80%两项分数。移除理论最高分、最高分词条分配及对应运行时穷举计算。历史最大值辅助函数仍供开发回归核对，不参与正常预测。

沿用现有N次随机强化模型：四词条、四档增量等概率；待激活第四条按已读值固定；主词条推进到+20后评分；+20只计算一次。相同圣遗物使用固定样本，切换候选不会改变该角色的分位数。缓存同时考虑词条和候选规则ID，关闭所有来源时不会回退全库。

如果已录入的新角色尚无本地评分规则，仍可被选中或由推荐匹配，表格标注“缺少评分规则”，两项分数为破折号。不会静默丢弃，也不复制其他角色权重。

本地只读核验：当前账号104条身份可进入选择表；黄金剧团可匹配芙宁娜89.4%、爱可菲76%、菲谢尔69%、千织64%、八重神子16.8%的四件套推荐。绝缘之旗印也可匹配已录入的两件套组合，验证了四件套/两件套两类数据均可使用。预览采用构造的圣遗物词条，不冒充新采集结果。

## 实现与验证

- `utils/strongbox-candidates.js`：已录入角色目录、三来源匹配、去重与排序、选择保存。
- `utils/artifact-projection.js`：动态规则候选、候选缓存键、稳定样本和完整分位数列表。
- `utils/mask-interaction.js`：F7穿透切换与监听清理。
- `assets/strongbox-mask.html`：来源开关、按元素角色表、评分列表和来源标记。
- `tools/verify-strongbox.mjs`：匹配、排序、单位/部位限制、空选择、缺权重、账号隔离、动态入口及HTML通信回归。

`node tools/verify-all.mjs`执行完整离线检查；`node tools/preview-strongbox.mjs <账号标识>`只读生成独立预览HTML。开发预览位于`tools/previews/`，不写回账号。已用本机Edge无界面渲染检查布局，尚需真实BGI/WebView2与游戏内测试F7、鼠标滚动和OCR。

交互实现参考BGI官方[HTML遮罩文档](https://www.bettergi.com/dev/js/htmlMask.html)及[键鼠回调文档](https://www.bettergi.com/dev/js/kmCallback.html)。`setClickThrough`是整个宿主窗口的开关，不能仅靠CSS实现透明区域穿透，因此需要明确的游戏/交互切换。
