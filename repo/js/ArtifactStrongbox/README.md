# 圣遗物三合一素材判断

Fork 的导入、脱敏、同步及部署方式见 [FORK.md](FORK.md)。公开仓库不含真实账号资料和私人参考截图。

BetterGI JS 脚本，用于在原神「还圣奥迹」素材选择界面识别圣遗物，结合账号已录入的角色装备与游戏内推荐，查看这件素材对各角色的保留价值。

**当前版本：0.9.3 · 试行版**。操作为「先录入角色资料，再手动选素材查看分析」。脚本提供逐角色结论，不自动合成、锁定或丢弃物品。

## 功能介绍

- **角色资料录入**：遍历角色，保存姓名、元素、五部位装备、推荐套装、主词条及追加词条；核对右下角装备者，避免把未装备部位默认选中的物品误记为现装。
- **素材识别**：读取名称、部位、套装、等级、主副词条；区分固定值与百分比，识别第四词条「待激活」，估算已强化命中次数。
- **强化预测**：模拟剩余强化至 +20，展示各角色的前20%／前80%评分。
- **逐角色取舍**：对照已录入现装，显示红色「舍弃」、黄色「待定」、绿色「保留」，顶部按角色汇总三色数量。
- **可选分析范围**：合并套装适配角色、拟培养角色，以及可选的沙／杯／冠主词条适配角色；支持按元素选择、中文／拼音／首字母搜索和列表滚动。
- **手动切换套装约束**：默认保护现有套装组合，也可关闭后单独考察属性评分。
- **账号隔离与日志**：按用户标识保存资料与培养名单，支持跳过完整角色和中断后再次录入。

## 安装与运行条件

1. 将整个 `ArtifactStrongbox` 文件夹放到 `BetterGI/User/JsScript/`，不要多嵌套一层文件夹。
2. 在 BetterGI 中刷新 JS 脚本列表，找到「圣遗物三合一素材判断」，打开 JS 自定义设置。
3. 使用原神**简体中文界面、16:9 默认布局**，推荐游戏分辨率 **1920×1080**。脚本要求 BGI 实际捕获图像为 1920×1080；其他尺寸会报错。高分辨率是否可用取决于捕获后的尺寸。
4. `manifest.json` 声明最低 BetterGI 版本为 **0.61.2**。当前代码已做离线回归，实际 OCR、加载时序和遮罩交互仍需在使用环境中核验。

BGI 运行时无需 Node.js、Python、npm 或联网下载数据，也不需要另装 `ArtifactScore`。

## 第一次使用：录入角色资料

1. 登录要录入的账号，填写 **用户标识**，建议使用该账号 UID。后续三合一分析必须填写相同标识；不同账号请使用不同标识。
2. 勾选 **运行角色仓库录入**。首次建议保持 **跳过已有数据角色** 关闭。
3. 建议从大世界界面启动。脚本会尝试按 Esc 返回，通过派蒙图标确认大世界后才按 C 进入角色界面；无法确认时停止。
4. 等待脚本依次读取角色身份、五部位现装与推荐信息。录入期间会自动切换页面，请避免手动切角色或同时运行其他会操作界面的脚本。
5. 遍历回到起始角色后结束；异常或停止时尝试保存已读取进度。查看 BGI 日志中的保存路径和待核对情况。
6. 录入结束后，**取消勾选运行角色仓库录入**，再次运行才会进入三合一分析。

动作后的主动等待默认约 **0.6秒**，截图、OCR 和失败重试另计。缺少「xxx已装备」或装备者不是当前角色时，该物品不会写为当前装备。未读全的资料可能使后续分析显示「待定」。

再次录入可开启 **跳过已有数据角色**，仅跳过身份、五部位装备与推荐都完整的角色；未识别或不完整的角色仍会重读。**换装后要更新基线，请关闭跳过选项重新录入**。同标识再次录入会覆盖已观察到的同字段。

## 日常使用：判断三合一素材

1. 关闭 **运行角色仓库录入** 和 **选择拟培养角色** 两个专项模式，确认用户标识与录入时一致。
2. 可填写 **当前圣遗物总量估计**，范围 0～2700；不知道时留空。
3. 在合成台进入「还圣奥迹」的素材选择界面，手动选中一件圣遗物，使右侧完整详情出现，再启动脚本。
4. 等待遮罩完成识别与计算。默认约每秒检查一次；首次计算和重试会增加等待时间。切换素材后会更新结果，离开对应界面时清除旧结果。
5. **按 F7 进入遮罩交互**，可切换选项、展开拟培养角色列表、搜索勾选和滚动评分表。交互期间暂停读取新截图，保留上一件结果。
6. **再次按 F7，或点「返回游戏」**，继续手动选素材。结束时使用 BGI 的停止当前脚本任务快捷键。

### 遮罩顶部选项

| 选项 | 默认 | 作用 |
| --- | --- | --- |
| 受现有套装限制 | 开启 | 保持角色现有四件套／两件套效果；拆套装时标为待定。关闭后只比较属性评分，并提示未计入套装效果损失 |
| 适配套装角色 | 开启 | 从已录入推荐中选出适用当前套装的角色，四件套使用率优先，再排两件套 |
| 用户培养角色 | 开启 | 加入自己勾选的拟培养角色，与其他来源取并集 |
| 匹配主词条（沙／杯／冠） | 关闭 | 加入该部位主词条推荐使用率**高于15%**的角色，辅助考察散件用途 |

**「适配套装角色」决定分析谁；「受现有套装限制」决定替换时是否保护该角色现装组合。** 二者独立。关闭套装限制不会自动把全部角色加入分析，也不会取消主词条适配和数据校验。

拟培养角色列表来自**当前账号已录入角色**，按元素分类。支持中文、全拼与首字母搜索，勾选名单按账号保存；来源与套装限制开关仅在本次运行有效，重启恢复默认。

## 如何理解分析结果

### 三色标签与顶部计数

| 标签 | 含义 |
| --- | --- |
| 🟢 保留 | 在当前评估模型与约束下，对该角色现装有较明确的提升价值 |
| 🟡 待定 | 分布未明显分开、模型分歧、会拆套装，或缺少可靠推荐／现装资料等；可悬停查看原因 |
| 🔴 舍弃 | 对该角色当前用途，提升可能性极低；或可靠推荐明确排除该主词条 |

顶部统计的是**角色数**，不是物品数。同角色有多个评分分支时，任一保留则计保留，否则存在待定则计待定，全部舍弃才计舍弃。没有分析角色时显示零，不代表这件物品可丢弃。

结论只覆盖本次开启来源匹配到的角色。一个角色的红色标签不能否定另一个角色的绿色用途；全部红色也不等于整账号或未来用途都无价值。当前不输出整件素材的最终单一决定。

### 评分列与颜色使用不同尺度

**前20%／前80%**：将模拟成品按原单件评分降序排列，取对应位置。前20%偏向较好结果，前80%偏向较差结果；不是提升概率，也不是实际伤害提升率。

**颜色判断**：使用推荐线性秩、推荐指数秩与原权重核验三个情景，对比素材强化结果和可靠的同部位 **+20现装**。当前试行标准为：三情景的有意义提升概率保守下界均不低于80%才判保留；任意正提升概率保守上界均不高于1%才判舍弃，其余待定。主词条范围排除另有规则。[详细判据](docs/role-assessment.md)

- 沙／杯／冠按已录入推荐中**使用率严格高于15%**的主词条判断适用范围。推荐覆盖不足时不把漏读当作不适配。
- 同主词条比较副属性；不同但均适配的主词条，须能统一计价后比较主副总分。无法可靠计价时待定，跨主词条判舍弃还要求明显落后。[主词条规则](docs/main-stat-policy.md)
- 模拟固定已知初始词条与待激活数值，只抽剩余强化；四词条命中与四档增量采用等概率试行模型。切换角色来源或套装限制使用相同样本。
- 非 **+0** 圣遗物名称会标红警示，仍可展示强化预测，但取舍标签保持待定。
- 基线来自启动时读取的录入快照，运行中换装不会自动更新。取消套装限制时可只用可靠的同部位现装，其他归属、完整性、满级检查仍保留。

### 仓库容量提示

| 手动估计总量 | 提示 |
| --- | --- |
| 留空 | 容量未知 |
| 0～2159 | 空间较宽裕 |
| 2160～2564 | 空间偏紧 |
| 2565～2700 | 接近满仓 |

2700是本脚本的参考容量。数量为静态估计，**三合一后不自动扣减**；目前只提示压力，不改变保留／舍弃阈值。需要时更新 JS 设置并重启。

## JS 自定义设置

修改后重新运行脚本生效。

| 设置 | 默认值 | 使用说明 |
| --- | --- | --- |
| 运行角色仓库录入 | 关闭 | 本次仅录入，完成后结束；优先于其他模式 |
| 跳过已有数据角色 | 关闭 | 仅在录入模式使用，跳过完整可靠资料；换装后更新现装时请关闭 |
| 选择拟培养角色 | 关闭 | 独立选择窗口，保存后结束；日常可直接在三合一遮罩中选择 |
| 用户标识 | 空 | 必填，用于隔离账号资料与培养名单，可填 UID |
| 当前圣遗物总量估计 | 空 | 0～2700整数；空为未知，不自动追踪数量 |
| 识别间隔 | 1000毫秒 | 最低500毫秒，是轮询等待，不保证完整一轮只花该时长 |
| 随机强化模拟次数 N | 10000 | 100～50000；增加次数会增加计算量，少量样本可能不足以支持明确判定 |
| 显示详情识别区域边框 | 关闭 | 用于确认详情裁剪位置，通常无需开启 |

## 常见问题

| 现象 | 处理方法 |
| --- | --- |
| 点击不到遮罩、无法滚动 | 按 F7 切换到遮罩交互；操作游戏前再按 F7 返回 |
| 遮罩中没有角色 | 核对用户标识，先运行角色录入，并检查至少开启一种有匹配结果的来源 |
| 没有读取新素材 | 确认已退出遮罩交互，当前处于还圣奥迹素材选择界面且详情可见 |
| 未识别到底部按钮／详情 | 检查简体中文、捕获尺寸与界面位置；可开启区域边框，查看 BGI 日志 |
| 很多角色显示待定 | 悬停查看具体原因；常见为缺推荐、现装未满级／归属未确认、拆套装或模型分歧 |
| 角色识别错误或录入中断 | 查看本次日志，重新录入；开启跳过完整角色可减少重复工作。不要把其他角色默认选中物品视为现装 |
| 换装后结论没有变化 | 关闭跳过选项重新录入，再以相同用户标识启动三合一 |
| 显示缺少评分规则 | 名称字典与评分库覆盖不同；录入成功不代表每个新角色或流派已有权重 |

姓名识别包含字典纠错；旅行者按元素记录为「旅行者（风／岩／雷／草／水／火／冰）」，流浪者与人偶通过介绍文字识别自定义身份。资料不稳定时保留待核对状态，不强行写入现装。

## 数据保存与更新

- **账号仓库**：`data/accounts/`。UID 对应 `uid-<UID>.json`，培养名单为相应 `.training.json`；另有保存过程中使用的 pending／backup 副本。请整目录备份。
- **运行日志**：`data/logs/`，按账号与运行分目录。启动日志会给出本次路径，含 `run.json` 与事件 JSON 分片，可辅助定位 OCR、导航和评分问题。
- **历史修正备份**：`data/name-migrations/`，如曾执行名称迁移则保留原始备份。

升级前备份上述目录及自己修改的 `assets/character-profiles.json`、`assets/decision-rules.json`。不要用他人的账号文件覆盖自己的资料。分享日志、参考图或整个项目时，注意其中可能包含 UID、角色别名和装备信息。[发布文件清单](RELEASE.md)

## 当前限制与数据来源

适用于当前固定布局下的五星圣遗物模型。OCR 显示值有取整误差；第四词条主要依据「待激活」文字区分，尚未使用像素颜色独立确认。没有读取角色整套实时面板、武器和命座，也没有进行全背包最优配装搜索，颜色不等于真实伤害收益或完整贝叶斯后验保证。

评分库为本地快照，参考 `ArtifactScore` 及 [miao-plugin](https://github.com/yoimiya-kokomi/miao-plugin)，包含本地覆盖和已记录的适配修改；并非在线同步的全部角色／流派数据库。角色姓名与拼音字典独立于评分库。原评分权重、来源哈希和 MIT 声明保存在 `utils/vendor/`。

`assets/character-profiles.json` 为可选手工角色分支配置；`assets/decision-rules.json` 仍是规则占位，**向其中添加条目不会直接执行新判据**。正常三色判断由当前评估实现负责。
